Stop typing sudo.But only for what you allowed.

TrustAuto is automatic privilege elevation for Linux. Type commands as usual, and whatever your policy allows runs as root. By default, unknown or high-risk commands ask for approval or are refused.

bash / zsh
journalctl -u nginx --no-pager Allowed by a rule. Runs with no password root
apt search vim Needs no privileges. Runs as you user
apt install ./evil.deb Fits no typed rule. Asks an approver ask
trustauto run -- mkfs -t ext4 /dev/sda Matches a deny rule. Does not run deny

By default, if no rule fits, nothing elevates on its own

Five kinds of rule decide the outcome. When several match, the strictest wins, whatever their order in the file.

  1. 0 0> <denydeny

    Never runs, in any mode.

  2. 0 0? ?askask

    Always asks for approval.

  3. 0 0^ ^rootallow

    Elevates right away. In the default hybrid, asks for approval if ML scores the risk high.

  4. 0 0? ?askenvelope

    Sets a range only. In the default hybrid, elevates only when ML scores the risk low, and asks otherwise.

  5. 0 00 0useruser

    Runs without elevating.

Rules listed first take priority

Typed arguments stop option injection

A deny list can never be complete. apt-get -o ... and find -exec are ordinary commands that can reach a root shell.

So your policy spells out each allowed command and the shape of its arguments. {pkg} and {unit} never match a value starting with -, so an option cannot slip in.

# /etc/trustauto/policy.toml
[[rule]]
id = "journal-unit"
action = "allow"
bin = "/usr/bin/journalctl"
args = ["-u", "{unit}", "--no-pager"]

[[rule]]
id = "no-mkfs"
action = "deny"
bin = "/usr/sbin/mkfs"
args = ["{any}*"]

No daemon. It runs only when you type a command

The code that runs as root is a separate small broker. It trusts nothing from the shell side, decides again for itself, then replaces itself with the command.

shell function → trustauto (unprivileged)
                  ├─ user verdict → runs as you
                  └─ trustauto-broker (setuid root)
                       ├ decides again
                       ├ writes the audit log (no log, no elevation)
                       ├ asks for PAM approval if needed
                       └ replaces itself with the command
0 MB
Extra memory when idle. There is no background process.
0.2 µs
Time for a decision the rules settle alone (p99, Linux VM). A decision that uses ML takes about 7 ms, plus about 26 ms to read the machine facts index built in advance. Excludes process start and policy parsing.
Audit log
Records each elevate, ask and deny verdict with its reason. If the log cannot be written, nothing elevates. user verdicts, which never elevate, are not recorded.

See what would happen before it happens

Most of the time you just type as usual. These commands are for when you want the reason, or want it off for a while.

trustauto explain -- apt install htopShows the verdict and reason without running anything.
trustauto history 20Shows past verdicts. Approvers see everyone's, others see their own.
trustauto off / onTurns your own automatic elevation off or on. Open shells follow right away.
trustauto settingShows whether it is on, the current mode, the state of the model and machine facts, and the network check.
trustauto checkValidates the policy file.

Install

For now you build from source. These steps assume Debian or Ubuntu.

  1. Build and install

    sudo apt install build-essential libpam0g-dev cargo
cargo build --release
sudo scripts/install.sh

  2. Set the policy

    Edit /etc/trustauto/policy.toml and list your approvers in approval.approvers. If it stays empty, everything that needs approval is refused.

    trustauto check

  3. Add users to the group

    sudo usermod -aG trustauto USERNAME

    Then log in again. Adding someone to this group hands them everything the policy allows.

  4. Load it in your shell

    Add this to ~/.bashrc. For zsh, add it to ~/.zshrc with bash changed to zsh.

    eval "$(trustauto shell-init bash)"

Before you install

This tool deals with root, so here is what it cannot do.

  • What you allow is open to every program that user runs

    Elevating without a password means it cannot tell a person from malware. Put in allow only what you could accept malware running as that user doing. Requiring a terminal stops most background jobs, but not ones that use a pseudo-terminal.

  • Commands that reach the network always ask

    apt update, apt install, curl, git pull, anything with a URL and the like need approval in every mode, even with an allow rule. Set ask = false under [network] in policy.toml if you do not want this.

  • No external audit

    For v1.0.0-preview.1, all 175 integration tests pass on one Ubuntu 26.04 (arm64) VM. Review it before installing on a machine you depend on.

  • Exit codes are not recorded

    The broker replaces itself with the command, so the history stops at the start.

  • Always runs in /

    Relative path arguments do not work in elevated commands.

  • Approval happens on the requesting terminal

    An approver on another terminal is not supported.

ML mode (research)

The default, hybrid, uses the ML risk score only inside the range your rules set. Whatever the model says, a command outside allow and envelope never elevates on its own. ml, which leaves commands outside the rules to ML as well, can be chosen as a preview.

ruleRules alone. allow elevates on the spot; envelope asks for approval.
hybrid (default)Rules and ML. allow elevates unless the risk score is high; envelope elevates only when it is low.
ml (preview, high risk)ML alone. A command that needs root elevates whenever the score is low, with or without a rule.

The model has not met its pass mark. Measured on four development machines, it let through 8 of 217 dangerous groups on a machine it had not seen (95% upper bound 6.6%) and allowed 71.2% of harmless commands automatically. There has been no final test on an independent machine yet.

In every mode, deny and ask come first. Even in ml, shells, interpreters and kernel or disk tools always ask, and so, by default, do programs the model had few training examples of.

ML reads the machine facts that trustauto-facts collects. If they are missing or more than 8 days old, everything that would go through ML asks an approver, and in the default hybrid that includes allow commands. Change the mode with sudo trustauto mode rule|hybrid|ml; trustauto setting shows the current state.
