# 実験 6: 重みの直接編集（中間層・ランク1・ニューロン・共通起点の補間）

実施: 2026-11-06。手順は [EDIT_PROTOCOL_V2.md](../ml/weight_space/EDIT_PROTOCOL_V2.md) で、編集を始める前に固定しました。コードと全結果は `ml/weight_space/` にあります（`pilot_v2.py`、`evaluate_v2.py`、`pilot_v2/<シナリオ>_seed<N>/`）。前段の出力層だけの試験は [pilot_v1/REPORT.md](../ml/weight_space/pilot_v1/REPORT.md) です。

## 結論

**目標は未達です。採用できる編集はありませんでした。** モデルは本体に組み込んでいません。

- 評価した 9 モデルのどれも、採用基準（新たな危険の誤承認 0、危険グループの片側 95% 上限 1.8% 未満、無害の自動許可 70% 以上）を満たしません。
- 活性化の統計から狙って作った編集（TFTV、平均ランク1、ニューロン増幅）は、同じ大きさのランダム編集を一貫して上回りませんでした。危険の見逃しを減らす点で、ヘッドのバイアスを足すだけの対照に勝ったものは 9 モデル中 0 です。
- 危険の見逃しが減った例は、ほぼすべて「全体を慎重側にずらした」結果です。同じ基準でしきい値を引き直すと、見逃しと無害の許可の関係はほとんど変わりません。つまり危険と無害の見分けは良くなっていません。
- 評価用データの危険グループ数は 51〜104 です。見逃し 0 でも、上限 1.8% 未満を示すには 165 グループ以上が必要なので、今のデータ量では合格を示せません。

## 方法

ベースライン 9 個（machine / target / operation × seed 1〜3）は、元の学習コード `fit_facts_transformer` をそのまま使い、30 エポック学習しました。読み込み直した予測が学習時と一致することを確認済みです（最大誤差 6e-8）。

しきい値は、ベースラインごとに校正用データの確定した危険行で決めました（1.8% 点）。どの候補でも同じしきい値を使います。統計は編集用データの「確定した危険」と「確定した無害」だけから取り、評価用データは選択が終わるまで開いていません。

1 モデルあたり 49 候補です（大きさは編集するテンソルに対する相対 L2 ノルムで 3%、10%、30%）。

| 種類 | 変える場所 | 数 |
|---|---|---|
| 元のまま | なし | 1 |
| TFTV（arXiv 2609.09054 の式 2 を応用。再現ではない） | 層 0・層 1 の FFN 出力 `linear2.weight`（2,048 要素） | 6 |
| 平均ランク1（危険−無害の方向 × 危険時の平均入力） | 層 1 の `linear2.weight` | 3 |
| ランダム・ランク1（対照） | 層 0・層 1、seed 11〜13、同じ大きさ | 18 |
| ニューロン増幅（危険で強く働く 4 ニューロンの出力を拡大） | 層 1 の `linear2.weight` の 4 列（128 要素） | 3 |
| ランダム・ニューロン（対照） | 同じ、4 列を seed で選択 | 9 |

選び方（編集用データだけで決定）: 新たに許可される確定危険行と Gemini 拒否行がともに 0 で、危険行の許可がベースライン以下の候補のうち、見逃しグループ数 → 見逃し行数 → 無害の許可数の順で良いもの。同点ならベースラインを選びます。

## 注意点

- 評価用データのうち machine（deb14）は、第1試験で見たあとです。target と operation も以前の実験で見た環境です。どれも開発用の証拠で、独立した最終評価ではありません。
- seed 2・3 は、scikit-learn を足した作業用の Python 環境で学習しました（PyTorch 2.9.1 は同じ）。seed 1 は前の会話の環境です。
- 同じモデル・同じしきい値でも、seed によって危険の見逃しが 1〜46 行と大きくばらつきます（target s3 は 46 行のうち 34 行が `program:passwd` の 1 グループです。スコアは 0.0017〜0.007 で、しきい値 0.038 より大きく下にあり、バイアスを 0.5 足しても届きません）。この不安定さは、編集よりもデータとモデルの側の問題です。
