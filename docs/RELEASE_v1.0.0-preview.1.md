# v1.0.0-preview.1 リリースノート

TrustAuto に ML の判定を組み込んだ最初のプレビューです。既定は「ML＋ルール」（`hybrid`）で、ML が判断するのはルールの範囲内だけです。ルールの外まで ML に任せる「ML のみ」は、管理者が選んだときだけ使われます。

## 何ができるようになったか

- `sudo trustauto mode hybrid` で、ルールの範囲内だけ ML が判断するモード（ML＋ルール）
- `sudo trustauto mode ml` で、ML だけが判断するモード（プレビュー、高リスク）
  - 選ぶと警告が出て、「MLが学習していないコードも判定して自動で認証しますか？（高リスク）」と聞かれます。既定は「いいえ」です。
  - シェル、インタープリター、エディタ、カーネルやディスクの操作は、どの設定でも承認待ちです。
- 外部と通信しうるコマンドは、どのモードでも既定で承認待ち（`[network] ask = true`）
- `trustauto-facts` が機械の事実を集め、毎日とパッケージ変更後に更新

## 使っているモデル

| 項目 | 値 |
|---|---|
| 方法 | 実験 5 round 4 の `known_avg_facts_transformer`（4 つの乱数の平均、学習にないプログラムは通さない） |
| 学習データ | 開発用の 4 台（`deb137`、`ubu2610`、`ubu24`、`deb14`）の確定した行 4,369 行 |
| しきい値 | 0.168（学習側の交差検証で、確定した危険な行の 1.8% を通す値） |
| 学習したプログラム | 191 個（許可された行が 3 行以上） |
| 精度（未見の機械、round 4） | 危険グループの見逃し 8/217（95% 上限 6.55%）、無害の自動許可 71.2% |
| 精度（未見の対象、round 4） | 危険グループの見逃し 12/217（95% 上限 8.81%）、無害の自動許可 45.2% |
| 合格基準 | 95% 上限 1.8% 未満、かつ無害 70% 以上 → **未達** |

精度はすべて開発データでの値で、独立した新しい機械での最終テストは行っていません。

重みを直接編集したモデル（`ml/weight_space/pilot_v1` の `activation_0.1`）は使っていません。deb14 での評価で、危険の見逃しは元のモデルと同じ 1/263 行のまま減らず、判断保留の行の自動許可が 118 → 130 行に増えたためです（[pilot_v1/REPORT.md](../ml/weight_space/pilot_v1/REPORT.md)、[実験 6](ML_EXPERIMENT_6.md)）。

## 互換性の注意

- 既定のモードが `rule` から `hybrid` になりました。機械の事実がない、または 8 日より古いと、`allow` ルールのコマンドも承認要求になります。
- v0.1.0 の `mode = "ml"` は意味が変わりました。範囲内だけ ML を使う動きは `hybrid` です。
- `apt update` など外部と通信するコマンドは、`allow` ルールがあっても承認が必要になりました。元に戻すには `[network] ask = false` にします。
- `[ml] low` はモデルのしきい値を厳しくする方向にだけ働きます。
